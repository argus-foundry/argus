# Resident memory, orientation and permissions

- **`kb_ingest` write-back used to drop every frontmatter key but `title`/`tags`**, which would silently strip `dream: skip` from resident working files. `kb.Document.Extra` now preserves other top-level frontmatter lines verbatim through `ParseDocument` and `RenderMarkdown`; it is not stored in the index.
- **Seeding goes through `kb.SeedVaultFile` (O_EXCL create, then `KBUpsert`), never an overwrite.** It runs on every resident start so a deleted working file reappears, but an agent-edited one is never touched. A seed failure is logged and non-fatal; the orientation prompt tells the agent to create a missing file.
- **The memory folder comes only from `resident.memory_dir`** (`residentMemoryDir`), never from `resident.name`, so a rename cannot move memory. A `..` dir is rejected by `SeedVaultFile`.
- **Allow/ask/deny tool rules are delivered as inline `--settings` JSON (`permissions.allow`/`ask`/`deny`)** through `Family.PermissionRulesFlag` (Claude only), gated on `task.IsResident()`. `BuildCmd` also strips `--dangerously-skip-permissions`/`--allow-dangerously-skip-permissions`/`--permission-mode` from the resident's backend command (`Family.StripPermissionFlags`) and forces `--permission-mode auto`, whatever `defaults.permission_mode` says; the rest of the command must then pass the flag allowlist (`Family.ResidentCommandCheck`, see `resident.md`), so `--allowedTools` is refused rather than stripped. `config.ResidentPermissionsEnforced` ships true with this.
- **Auto retains explicit ask/deny rules, while narrow allows bypass classifier review; blanket arbitrary-execution allows are suspended only while auto is active.** The shipped resident no longer allows bare Bash, so Manual fallback cannot silently approve every shell action; user `resident.allow_tools` overrides can still widen it. Verified against [official permission-mode docs](https://code.claude.com/docs/en/permission-modes#how-auto-mode-evaluates-actions) and Claude Code 2.1.325 (2026-11-14); precedence stays deny > ask > allow.
- **Testing this headless: user-level hooks contaminate the result.** Aaron's `PermissionRequest` hook for `Bash` auto-approves, so with user settings loaded an ask rule on Bash looks ignored. Use `--setting-sources project`, pass flags as separate arguments (a quoted `"--permission-mode default"` is one unknown option), redirect stdin from /dev/null, and note Claude's `echo` is always auto-allowed. Connector (MCP) tools are not hit by that hook. A live check against a real connector tool was not run.
- **Supported resident Bash/MCP PermissionRequest prompts are denied into durable board approvals; pending board items are not ResidentWaiting.** Both matcher and binary exclude questions/plan dialogs. Debounce belongs to one rendered chooser: unrelated hook traffic never refreshes its15s maximum, and generic proceed prose is never a permission marker.
- **Bash description is not execution identity.** Exclude only that field from grants; keep command, timeout and all other fields exact, and include canonical stored input in the approval notice so Solo can retry after compaction. Hook crash/timeout with onFailure:block was proven to block and continue on Claude Code2.1.325 in print/PTy and default/auto modes.
- **`task_recycle` is in `allow_tools` because the connection is caller-bound.** Its target comes from a caller-supplied `id`/`cwd`, so the resident's spawn-time Argus MCP URL carries `?caller=<resident task id>` (agent.go, resident only) and `handlePOST` stores it on the unexported `Request.caller` (never read from the body). `toolTaskRecycleAs` then refuses any target other than the caller for ANY bound connection (fail closed, no DB lookup). The binding restricts every bound caller to itself, and it is also the only way to recycle the resident: an unbound or foreign caller targeting the resident is refused. The caller is an unauthenticated localhost query parameter, so a local process that forges the resident's id could recycle it (no worse than the unbound access that existed before). Residual: the binding is not exclusive. There is no `--strict-mcp-config`; the resident's connectors are account-level claude.ai connectors (kept regardless of setting sources), not user `.claude.json` servers, so an agent that reconfigured its own MCP via Bash (subject to auto review or Manual approval) could reach an unbound `argus` server; accepted. The agent cannot alter its own spawn flags. `kb_ingest` and `slack_send_message_draft` stay allowed by design (spec); they are the accepted residual prompt-injection surface.
- **The resident's Stop hook only looks the resident up when `ARGUS_RESIDENT=1` is set** (exported by `BuildCmd` for the resident spawn alone, next to `ARGUS_TASK_ID`), so plain tasks make no extra RPC per Stop. `BuildCmd` also filters any inherited `ARGUS_RESIDENT` (and a backend `env_vars` entry) in the final env pass that reserves `ARGUS_SANDBOXED`, then appends it only for the resident, so a daemon started from a resident shell cannot leak it to plain tasks. The marker only gates the lookup; the `ResidentState` RPC still confirms identity, and a stale supervisor that spawned the resident without it simply skips resident Stop handling until restarted.
- **Bypass-flag stripping uses a shell-words tokenizer, not `strings.Fields`, and splices by word range:** the command runs under `sh -c`, so each top-level word is compared by its POSIX quote-removed value (`"--dangerously-skip-permissions"`, `--flag""`, `--permission-mode="x"` and `"--permission-mode" plan` are all real flags and get stripped, with the value word for the two-word form), while a quoted argument that merely contains the text survives byte-for-byte. Kept words and the separator text between them are copied verbatim and nothing is trimmed: trimming after a drop ate whitespace owned by the previous kept word (a `\<newline>` continuation left a dangling backslash that swallowed the appended `--permission-mode default`; an escaped trailing space joined the next flag into the previous value). An unquoted `\<newline>` between words is a separator. An unparseable command (unbalanced quote) refuses the resident launch rather than risk a dropped forced mode. Tests run the output through a real `sh` and assert the exact argv.
- **`api.enabled` is a resident prerequisite** (`ResidentPrereq`): the unread marker, reply preview, waiting flag and budget nudge all ride the REST API (reply stamp, budget read, idle watcher), so without it they would fail silently.
- **The resident's permission policy is self-contained: `--setting-sources project` + inline `--settings`.** Verified headless (Claude Code 2.1.317): `ask` beats `allow` regardless of specificity or source, `deny` removes the tool, but a tool the resident lists nowhere is auto-allowed by the user's wildcard allow rules, so user settings are dropped entirely (permissions, hooks, enabledPlugins, user skills/CLAUDE.md, user `.claude.json` mcpServers, model/effort/env). `project` MUST stay a source: builtin skills arrive via `--add-dir` and are only discovered with it; `local` is deliberately excluded so "don't ask again" answers in the resident dir's `.claude/settings.local.json` cannot silently grow the allow list. Inline `--settings` still applies under any source set, claude.ai connectors, `--plugin-dir` (bridge mod), `--mcp-config`, `--append-system-prompt-file` and auth are unaffected.
- **What the inline settings re-supply (BuildCmd, resident only).** `permissions` (allow/ask/deny + `defaultMode: auto` + `disableBypassPermissionsMode: disable`); a `Stop` hook running `<spawning argus executable> coord-hook` (the global registration is the bare `argus coord-hook`, which the dropped user settings no longer provide; absolute `os.Executable` path, quoted only when needed); the account `settings.json`'s `permissions.deny`/`permissions.ask` merged into the resident's own lists (never its `allow`; a user `ask` for a tool the resident allows therefore makes it prompt); and the account's `model`/`effortLevel` only when nothing else chose a model. Read is best-effort from `<account config dir>/settings.json` (the default account reads `~/.claude`; an inherited `$CLAUDE_CONFIG_DIR` is ignored because spawnBaseEnv strips it); failure logs and falls back to the resident's lists.
- **User CLAUDE.md and user skills are re-added without user settings.** Claude keeps only the LAST `--append-system-prompt-file` (verified), so the routing content and the account `CLAUDE.md` are concatenated into one file, `~/.argus/resident-launch/system-prompt.md`. Claude discovers skills only under `<added dir>/.claude/skills` (`<dir>/skills` is not scanned), so a per-account dir under `~/.argus/resident-launch/skills/<hash>/` carries a `.claude/skills` symlink to the account's `skills/` and is passed as an extra `--add-dir` (verified to load under `--setting-sources project`, symlink included). Claude.ai-synced (`anthropic-skills:*`) and plugin skills do not survive. A missing CLAUDE.md or skills dir is skipped.
- **Resident inbox tools.** `task_inbox` and `task_message_ack` are allowed (own messages only); `task_message_send` is in ask because it types into other agents' sessions.
- **The resident's launch files live in `~/.argus/resident-launch/` (0700, files 0600), outside every sandbox write grant.** `~/.argus/cache` is writable by every sandboxed agent and `~/.argus/resident` is the resident's own worktree grant, so a prompt file or skills link in either could be rewritten (TOCTOU) by the agent whose policy it carries; the data-dir root is granted to no sandbox (same placement as `~/.argus/routing`). `TestResidentLaunchDir_NotWritableBySandbox` parses a generated SBPL profile to pin it. `residentLaunchDir`/`ensurePrivateDir` use Lstat and replace a planted symlink or file instead of following it; the prompt file has a fixed name (no growth), is compared byte-for-byte on every launch (regular files only) and rewritten by O_EXCL temp file + rename, which never writes through a symlink; the skills link is rebuilt the same way (parents re-checked, wrong target replaced). Residual: the SOURCES (`~/.claude/CLAUDE.md`, `~/.claude/skills`) are writable by sandboxed Claude agents via the existing `~/.claude` grant, pre-existing for every Claude agent and not closed here (named follow-up `resident-source-integrity`, see `resident.md`).

- **External connector grants must stay concrete: Claude Code ignores global `mcp__*` allow rules, and whole-server/read-name wildcard grants can approve unknown writes.** Unmatched tools receive auto review (or prompt in Manual); deny > ask > allow preserves user restrictions and structural Hera guards over the broader Argus allow.
- **Auto launch and fallback diagnostics require supervisor surfaces 51/19 and a resident session restart after installing.** A daemon-only bounce reattaches the existing resident with its previous argv and inline policy; use a Claude Code version supporting auto (2.1.325 verified; 2.1.323 fixed native safe-fallback behavior).
- **Unattended resident workers still run bypass and deny only explicit resident ask/deny rules.** A newly added connector write absent from those lists can run in a worker even though the resident itself would review it in auto or ask in Manual; refresh inventories or add explicit deny overrides until complement-based worker enforcement is designed.

- **Connector display-name casing can change after review: expand resident rules at delivery, including user restrictions and worker denials.** `ExpandResidentConnectorRules` emits historical/lowercase aliases for reviewed servers while keeping tool suffixes literal; a new server spelling still needs an explicit alias review. See [the alias decision and catalog check](../../spikes/2026-11-12-resident-connector-aliases.md).

- **Auto fallback diagnostics are best-effort and go to the supervisor log through slog; supervisor uxlog is uninitialized.** Notice wording may change (no real unavailable-mode capture was induced); parse ANSI/UTF-8 incrementally, treat cursor moves as spaces, retain 4 KiB of complete text, and stop after 64 KiB or 60 seconds from launch without retrying work.
- **Auto blocks are not automatically waiting.** Explicit asks and repeated-block/context escalation use the numbered chooser, while repeated missing verdicts can stop with an instruction to send a message or switch modes; only that terminal stop at an idle prompt raises waiting, not transient classifier notices; the rule applies to all Claude tasks, including non-residents. Source: [Claude Code error reference](https://code.claude.com/docs/en/errors#the-server-returned-no-safety-verdict), 2026-11-14.
- **Classifier review does not guarantee confirmation for Git/gh outward actions.** The shipped policy has no push or gh allow rules; add explicit ask rules only when an unconditional human checkpoint is wanted, since auto may approve same-repo pushes and requested PRs ([common boundaries](https://code.claude.com/docs/en/auto-mode-config#common-boundaries)).
- **Keep read-only Bash grants narrow in both mode and operands.** Only ls/cat/head/tail/grep/wc and git status have shipped prefix grants; rg --files, find . -type f and git log/diff/show/branch are exact commands because extra options can execute programs or mutate state (rg --pre, find -exec/-delete, Git --output/--ext-diff and branch -D).

- **Consume exact grants at PermissionRequest, never PreToolUse: a PreToolUse allow cannot override ask rules.** Preserve full canonical input with UseNumber and reject duplicate JSON keys; no input rewriting or permission updates. Grant consumption authorizes one attempt, never proves tool completion; each restart/account move rotates the private credential and invalidates earlier grants.
- **Approval display must be literal.** Ordinary board Markdown strips `**` and normalizes whitespace, changing what a human reviews; approval bodies preserve both and escape directional/control characters. Generic board updates and resolution cannot alter approval records or authorize execution.
- **Deferred approvals require supervisor spawn surface 52 and a Solo restart.** Install the new binary, restart daemon and supervisor, then restart Solo to install its authenticated PermissionRequest hook. The hook credential stays in private `resident-launch/approval-hook.json`, never argv/env; argv carries only its public fingerprint, so stale hooks cannot read a replacement launch's token.
- **A live bridge has no dialog event for the terminal missing-verdict stop.** Daemon resolution preserves that specific scraper-confirmed failure in waiting and shared bridge snapshots, with the marker bound to the process launch generation so a same-transcript restart cannot inherit it.
