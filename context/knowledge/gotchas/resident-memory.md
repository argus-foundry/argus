# Resident memory, orientation and permissions

- **`kb_ingest` write-back used to drop every frontmatter key but `title`/`tags`**, which would silently strip `dream: skip` from resident working files. `kb.Document.Extra` now preserves other top-level frontmatter lines verbatim through `ParseDocument` and `RenderMarkdown`; it is not stored in the index.
- **Seeding goes through `kb.SeedVaultFile` (O_EXCL create, then `KBUpsert`), never an overwrite.** It runs on every resident start so a deleted working file reappears, but an agent-edited one is never touched. A seed failure is logged and non-fatal; the orientation prompt tells the agent to create a missing file.
- **The memory folder comes only from `resident.memory_dir`** (`residentMemoryDir`), never from `resident.name`, so a rename cannot move memory. A `..` dir is rejected by `SeedVaultFile`.
- **Allow/ask/deny tool rules are delivered as inline `--settings` JSON (`permissions.allow`/`ask`/`deny`)** through `Family.PermissionRulesFlag` (Claude only), gated on `task.IsResident()`. `BuildCmd` also strips `--dangerously-skip-permissions`/`--allow-dangerously-skip-permissions`/`--permission-mode` from the resident's backend command (`Family.StripPermissionFlags`) and forces `--permission-mode default`, whatever `defaults.permission_mode` says; the rest of the command must then pass the flag allowlist (`Family.ResidentCommandCheck`, see `resident.md`), so `--allowedTools` is refused rather than stripped. `config.ResidentPermissionsEnforced` ships true with this.
- **Live check (claude 2.1.317, headless `claude -p`, Bash rules, `--setting-sources project`):** under `--permission-mode default` an allow rule ran, an ask rule was held, a deny rule was blocked and an unlisted command was held. Under `--dangerously-skip-permissions` ask and deny were also held, but unlisted commands ran. So in this version ask is honoured under bypass too; default mode is still forced because it is the stricter, version-independent choice, which is why `[resident] allow_tools` exists: in default mode anything unlisted prompts, so ordinary built-ins, Argus tools, connector reads and drafts must be allow-listed. Deny always wins; concrete entries remain disjoint (`TestDefaultResidentConfig_TiersAreDisjoint`), while the Argus wildcard deliberately overlaps structural ask/deny rules.
- **Testing this headless: user-level hooks contaminate the result.** Aaron's `PermissionRequest` hook for `Bash` auto-approves, so with user settings loaded an ask rule on Bash looks ignored. Use `--setting-sources project`, pass flags as separate arguments (a quoted `"--permission-mode default"` is one unknown option), redirect stdin from /dev/null, and note Claude's `echo` is always auto-allowed. Connector (MCP) tools are not hit by that hook. A live check against a real connector tool was not run.
- **A pending confirmation is Claude's numbered permission prompt**, flagged by the ordinary needs-input detector; the API tick strips the resident from the generic set and exposes it as `ResidentWaiting` (`TestResident_PendingConfirmationRaisesWaiting`).
- **`task_recycle` is in `allow_tools` because the connection is caller-bound.** Its target comes from a caller-supplied `id`/`cwd`, so the resident's spawn-time Argus MCP URL carries `?caller=<resident task id>` (agent.go, resident only) and `handlePOST` stores it on the unexported `Request.caller` (never read from the body). `toolTaskRecycleAs` then refuses any target other than the caller for ANY bound connection (fail closed, no DB lookup). The binding restricts every bound caller to itself, and it is also the only way to recycle the resident: an unbound or foreign caller targeting the resident is refused. The caller is an unauthenticated localhost query parameter, so a local process that forges the resident's id could recycle it (no worse than the unbound access that existed before). Residual: the binding is not exclusive. There is no `--strict-mcp-config`; the resident's connectors are account-level claude.ai connectors (kept regardless of setting sources), not user `.claude.json` servers, so an agent that reconfigured its own MCP via Bash (allowed by the widened resident defaults) could reach an unbound `argus` server; accepted. The agent cannot alter its own spawn flags. `kb_ingest` and `slack_send_message_draft` stay allowed by design (spec); they are the accepted residual prompt-injection surface.
- **The resident's Stop hook only looks the resident up when `ARGUS_RESIDENT=1` is set** (exported by `BuildCmd` for the resident spawn alone, next to `ARGUS_TASK_ID`), so plain tasks make no extra RPC per Stop. `BuildCmd` also filters any inherited `ARGUS_RESIDENT` (and a backend `env_vars` entry) in the final env pass that reserves `ARGUS_SANDBOXED`, then appends it only for the resident, so a daemon started from a resident shell cannot leak it to plain tasks. The marker only gates the lookup; the `ResidentState` RPC still confirms identity, and a stale supervisor that spawned the resident without it simply skips resident Stop handling until restarted.
- **Bypass-flag stripping uses a shell-words tokenizer, not `strings.Fields`, and splices by word range:** the command runs under `sh -c`, so each top-level word is compared by its POSIX quote-removed value (`"--dangerously-skip-permissions"`, `--flag""`, `--permission-mode="x"` and `"--permission-mode" plan` are all real flags and get stripped, with the value word for the two-word form), while a quoted argument that merely contains the text survives byte-for-byte. Kept words and the separator text between them are copied verbatim and nothing is trimmed: trimming after a drop ate whitespace owned by the previous kept word (a `\<newline>` continuation left a dangling backslash that swallowed the appended `--permission-mode default`; an escaped trailing space joined the next flag into the previous value). An unquoted `\<newline>` between words is a separator. An unparseable command (unbalanced quote) refuses the resident launch rather than risk a dropped forced mode. Tests run the output through a real `sh` and assert the exact argv.
- **`api.enabled` is a resident prerequisite** (`ResidentPrereq`): the unread marker, reply preview, waiting flag and budget nudge all ride the REST API (reply stamp, budget read, idle watcher), so without it they would fail silently.
- **The resident's permission policy is self-contained: `--setting-sources project` + inline `--settings`.** Verified headless (Claude Code 2.1.317): `ask` beats `allow` regardless of specificity or source, `deny` removes the tool, but a tool the resident lists nowhere is auto-allowed by the user's wildcard allow rules, so user settings are dropped entirely (permissions, hooks, enabledPlugins, user skills/CLAUDE.md, user `.claude.json` mcpServers, model/effort/env). `project` MUST stay a source: builtin skills arrive via `--add-dir` and are only discovered with it; `local` is deliberately excluded so "don't ask again" answers in the resident dir's `.claude/settings.local.json` cannot silently grow the allow list. Inline `--settings` still applies under any source set, claude.ai connectors, `--plugin-dir` (bridge mod), `--mcp-config`, `--append-system-prompt-file` and auth are unaffected.
- **What the inline settings re-supply (BuildCmd, resident only).** `permissions` (allow/ask/deny + `defaultMode: default` + `disableBypassPermissionsMode: disable`); a `Stop` hook running `<spawning argus executable> coord-hook` (the global registration is the bare `argus coord-hook`, which the dropped user settings no longer provide; absolute `os.Executable` path, quoted only when needed); the account `settings.json`'s `permissions.deny`/`permissions.ask` merged into the resident's own lists (never its `allow`; a user `ask` for a tool the resident allows therefore makes it prompt); and the account's `model`/`effortLevel` only when nothing else chose a model. Read is best-effort from `<account config dir>/settings.json` (the default account reads `~/.claude`; an inherited `$CLAUDE_CONFIG_DIR` is ignored because spawnBaseEnv strips it); failure logs and falls back to the resident's lists.
- **User CLAUDE.md and user skills are re-added without user settings.** Claude keeps only the LAST `--append-system-prompt-file` (verified), so the routing content and the account `CLAUDE.md` are concatenated into one file, `~/.argus/resident-launch/system-prompt.md`. Claude discovers skills only under `<added dir>/.claude/skills` (`<dir>/skills` is not scanned), so a per-account dir under `~/.argus/resident-launch/skills/<hash>/` carries a `.claude/skills` symlink to the account's `skills/` and is passed as an extra `--add-dir` (verified to load under `--setting-sources project`, symlink included). Claude.ai-synced (`anthropic-skills:*`) and plugin skills do not survive. A missing CLAUDE.md or skills dir is skipped.
- **Resident inbox tools.** `task_inbox` and `task_message_ack` are allowed (own messages only); `task_message_send` is in ask because it types into other agents' sessions.
- **The resident's launch files live in `~/.argus/resident-launch/` (0700, files 0600), outside every sandbox write grant.** `~/.argus/cache` is writable by every sandboxed agent and `~/.argus/resident` is the resident's own worktree grant, so a prompt file or skills link in either could be rewritten (TOCTOU) by the agent whose policy it carries; the data-dir root is granted to no sandbox (same placement as `~/.argus/routing`). `TestResidentLaunchDir_NotWritableBySandbox` parses a generated SBPL profile to pin it. `residentLaunchDir`/`ensurePrivateDir` use Lstat and replace a planted symlink or file instead of following it; the prompt file has a fixed name (no growth), is compared byte-for-byte on every launch (regular files only) and rewritten by O_EXCL temp file + rename, which never writes through a symlink; the skills link is rebuilt the same way (parents re-checked, wrong target replaced). Residual: the SOURCES (`~/.claude/CLAUDE.md`, `~/.claude/skills`) are writable by sandboxed Claude agents via the existing `~/.claude` grant, pre-existing for every Claude agent and not closed here (named follow-up `resident-source-integrity`, see `resident.md`).

- **External connector grants must stay concrete: Claude Code ignores global `mcp__*` allow rules, and whole-server/read-name wildcard grants can approve unknown writes.** New connector tools, including new reads, still prompt until reviewed; deny > ask > allow preserves user restrictions and structural Hera guards over the broader Argus allow.
- **Widened defaults require a supervisor restart (spawn surface 46) and a resident session restart after installing the new binary.** The supervisor owns `BuildCmd`; a daemon-only bounce reattaches the old resident with its old inline policy. Bash is allowed inside the Argus sandbox, so connector permission lists do not prevent outward actions through CLI/network APIs.
- **Unattended resident workers still run bypass and deny only explicit resident ask/deny rules.** A newly added connector write absent from those lists can run in a worker even though the resident itself would ask; refresh inventories or add explicit deny overrides until complement-based worker enforcement is designed.
