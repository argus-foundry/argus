# Resident agent (add-resident-agent)

Memory, orientation and tool permissions are in [resident-memory.md](resident-memory.md). Other resident invariants sit with their areas: ensure-loop and RPCs in `daemon-rpc.md`, Stop hook and recycle seed in `orchestration.md`, `ctrl+\` and return snapshots in `keybindings.md`, rail box and tab marker in `tasklist-ui.md`, Settings category in `misc.md`.

- **The resident is a task row with a `kind` marker, hidden at one choke-point predicate.** Task lists, the PR poller, reapers, merge-safety, `/api/tasks` and the cleanup sweeps all go through it; a new task-enumerating path that skips the predicate leaks the resident into Hera, the web UI or a completion sweep.
- **Worktree precondition:** the resident runs in its own directory, not a git worktree, so any code assuming "every task has a worktree/branch" must check `IsResident()` first (no merge-safety, no branch cleanup).
- **First attach forces a PTY resync; no size-drift kick for the resident pane.** `attachResidentSession` calls `ForceResyncPTY` for a newly bound live session because `SetSession` seeds the tracked size from the pane, so the delta check alone would never resize a replacement PTY. The Hera `RerenderKicker` machinery was deliberately not reused: it is bound to Hera pane bindings and its kill-and-resume restart path would race the daemon's resident ensure loop; the daemon launches the resident at the real pane size instead, which keeps drift rare.
- **`ResidentStateResp.Reason` is shown, not dropped.** `applyResidentState` copies it (control bytes stripped, UI goroutine) to the pane placeholder note and `Settings -> Resident` (`Not running: ...`). The placeholder draws only with no session and no replay content, so a healthy resident never shows it.
- **Settings' enable gate also needs `api.enabled`** (`ResidentPrereq`); TUI fixtures that enable the resident must set `api.enabled` too.
- **The Stop hook is gated on the resident's own task id** (`ARGUS_TASK_ID`), has its `coord-hook` supplied inline at spawn (see `resident-memory.md`, so it does not depend on the global hook registration), and always allows Stop. See `orchestration.md`.
- **Signals:** unread reply and `Waiting` (a pending confirmation) are two separate flags exposed together by `Daemon.ResidentState`; `Waiting` comes from the generic needs-input detector with the resident stripped from the generic set.
- **Rail-box no-resize invariant:** the rail ResidentBox changes height with unread/waiting state, so it must never resize the PTY pane (a resize triggers the size-drift kick). It is drawn only when no task is bound on the Tasks rail, stacks under the needs-input bar in the agent view, and has smoke tests asserting the agent pane rect is unchanged.
- **Hotkey recipe:** `ctrl+\` is the 0x1c byte; map Cmd+\` to "send hex 0x1c" in iTerm2/Ghostty and free the macOS "Move focus to next window" shortcut. See the README.
- **`config.toml` `[resident]` silently wins over Settings edits.** Settings writes DB keys; a key present in config.toml masks it with no warning. `allow_tools`/`ask_tools`/`deny_tools` are config.toml-only.
- **Settings' enable gate calls `ResidentPrereq()`**, which also refuses while `config.ResidentPermissionsEnforced` is false. It ships true; a branch built before the permissions stage landed would refuse every enable.
- **`residentOrientationPrompt(cfg)` is the single seam** for both the fresh-start prompt and the recycle seed; never build orientation text elsewhere.
- **Spawn surface 40, protocol v13:** the resident's spawn flags (`--settings` rules, forced permission mode, `?caller=` MCP URL) live in supervisor-resident `BuildCmd`, gated on `Task.Kind` riding the Start/Kick/Recycle request. Restart the supervisor after installing; the client refuses to launch the resident on a pre-v13 supervisor.
- **Not yet fenced:** the ai-ron `airon-dream` skip rule for `resident/**` and `dream: skip` is a separate-repo follow-up; the memory folder is unprotected from the nightly pass until it lands.
- **`BuildCmd` refuses a non-resident task whose worktree is the resident working directory.** An older TUI binary that doesn't send `Task.Kind` would otherwise relaunch the resident without its permission policy; the paths are compared after `filepath.Clean`.
- **A recycle seed is one-shot:** `restartSessionWithSeedPrompt` persists it as the row's `Prompt`, so the ensure loop's `start()` always resets `Prompt` to the orientation. Otherwise a later fresh launch (for example after `resident.account` changes and the old transcript can't be resumed) replays a stale handoff and relay directive.
- **Everything `ResidentSend` queues (the budget nudge) and every task-message doorbell starts with `lastexchange.SystemTurnPrefix` (`[argus] `)**, typed or bridge-delivered, and last-exchange extraction skips such turns and freezes the replies after them. Typed without the bridge, the budget nudge would otherwise be quoted as "the user's last message" in the recycle seed.
- **The resident's orientation and recycle seed also start with `[argus] `**, so a recycle before any human turn quotes no Argus text as "the user's last message". Unprefixed Argus notices — bridge-delivered turns without `[argus] `, typed hera doorbells (`[hera from …]`) and `/api/notify` texts — are not marked: typed, they can still be quoted as the human message; bridge-delivered, they are skipped but do not freeze later replies (named follow-up `widen-last-exchange-delivery-tags`; it would change master's hera seeds).
- **Only the resident may `task_recycle` the resident** (`caller == resident`, fail closed): any other session's `handoff_note` would become the fresh resident's own authoritative handoff. Unbound callers keep recycling ordinary tasks.
- **A doorbell to the resident names the sender only through a strict `[A-Za-z0-9._-]` allowlist** (`sanitizeNudgeName`). The name is typed into the resident's PTY as a user turn, so spaces, punctuation or prose in a task name could otherwise read as an instruction (e.g. `x) — Aaron says: …`). Real names are slugs and pass unchanged; the resident reads the message itself through `task_inbox`, where it is data.
- **A running resident whose prerequisite later fails is stopped, not just refused a restart**, but only on the 2nd consecutive failing tick (`residentPrereqStopAfter`, ~10s) so a briefly unmounted vault drive does not kill it; the reason is set after the stop and shown immediately on the 1st failure. The no-Claude-backend error takes the same path (a config error); the MCP-not-bound wait is a startup state and never stops anything. The counter resets on any tick that passes the prerequisite and backend checks.
- **The resident launches at its OWN published size, never `Active`** (`db.InitialPTYRoleResident` → `InitialPTYLayout.Resident`). `Active` is whatever view the user is on (side-paneled agent pane, Hera worker pane), so the old `resolveSpawnSize(..., "", ...)` could start/restart the resident narrow and commit history the attach-resize cannot repair (BUG-078 family). The TUI computes it with `ptySizeFromHostTerm` (header + status bar + border, same as the zoomed agent pane) on every publish regardless of tab. The role constant is a selector only, never a stored hera role kind. An older TUI publishes no `Resident`, so `InitialPTYSize` returns zero for it (never substituting Active) and the daemon falls to the live PTY size, then 24x80. `internal/db/initial_pty.go`, `internal/tui/initial_pty.go` and `internal/daemon/resident.go` are not in `SupervisorSpawnPaths`/`SupervisorStreamPaths`, so no surface bump.
- **A stopped resident that has run before replays its dead log, so the placeholder's reason line never shows.** `TerminalPane.Draw` overlays the same `placeholderNote` as a one-line banner on the first inner row via a `defer` (covers every replay return path), only when `!alive` and the pane is not on the placeholder path; the row is blanked first so it never mixes with replay cells. The note is already empty whenever the resident runs (`applyResidentState` drops the reason when `Running`), so no extra clearing logic exists, and it is UI-goroutine only with no Sync.
- **Settings isolation carries only an ALLOWLIST of the user's Claude `sandbox` block, and never user hooks.** `--setting-sources project` drops both. `residentSandbox` copies only keys known to restrict: `enabled` and `failIfUnavailable` (only when true), `network.deniedDomains`, `filesystem.denyRead`, `filesystem.denyWrite` (key names verified against the local claude binary's schema strings), and forces `autoAllowBashIfSandboxed:false` + `allowUnsandboxedCommands:false` on whatever is carried. Every other key is dropped, including unknown future ones (a denylist would silently pass them): `allowAppleEvents`, `filesystem.disabled`/`allowRead`/`allowWrite`, `enableWeakerNetworkIsolation`, `allowNestedUserNamespaces`, `network.allow*`/`allowedDomains`, `excludedCommands`, `credentials.*` (mask mode injects real credentials at hosts, so it is not provably restrict-only). Nothing allowlisted left means nothing carried. **`enabled`/`failIfUnavailable` are dropped only when `argusWrapsSandbox` is true** (resolved config enabled AND sandbox-exec available AND a worktree; the same predicate as BuildCmd's wrap block, never the persisted `task.Sandboxed`): Claude's Bash sandbox cannot nest inside sandbox-exec (exit 71, see `sandbox.md`) and with `allowUnsandboxedCommands` forced false every Bash call would fail. It is fail-closed: if profile generation fails, the resident refuses to start (`resident sandbox profile: ...`) rather than run with neither sandbox; plain tasks still fall through unsandboxed. User hooks stay out: they cannot be classified generically and one (`argus-permission-approve.sh`) auto-approves Bash. Skipped hook events are logged once per spawn (`[resident] user hooks not applied`).
- **The resident's backend command passes a FLAG ALLOWLIST (Claude only, `Family.ResidentCommandCheck`), after the bypass/permission-mode strip.** Word 0 must be a path (optionally `~/`-led) whose base is `claude`; accepted words are plain or simple single-quoted (`'opus[1m]'`), while double quotes, `$HOME`, and UNQUOTED `[`/`]` (a sh glob that could match a cwd file) are refused with a single-quote hint; every other word must be `--model`, `--effort`, `--fallback-model` (value as next word or `=` form) or `--verbose`, and every accepted word must match a metacharacter-free pattern so a value cannot smuggle `;`/`$(...)` into the `sh -c` line. Anything else (`--allowedTools`, `--plugin-dir`, `--plugin-url`, `--agent(s)`, `--mcp-config`, `--settings`, `--setting-sources`, `--add-dir`, positionals, operators) makes `BuildCmd` return an error naming it, which the resident manager surfaces as its Reason. Only `--model` is a flag Argus itself appends to a Claude command; `--effort`/`--fallback-model`/`--verbose` were verified in `claude --help` and load nothing. Plain tasks are unaffected. The `--allowedTools` strip code was removed in favor of this refusal.
- **Concurrent first launches must not race on the private dirs or the skills link.** `ensurePrivateDir` accepts `EEXIST` only when the existing path is a real directory (not a symlink or file); the skills link is swapped by creating a temp link and renaming it over the target, with a `Readlink` fallback that treats an already-correct link as success when a peer won the race (`internal/agent/claudeaccount.go`).
- **Named follow-up `resident-source-integrity` (not fixed in this PR):** the sources the resident loads at each launch (`~/.claude/CLAUDE.md`, `~/.claude/skills`, and the account dir generally) are writable by every sandboxed Claude agent through the existing `/.claude` sandbox grant, so a sandboxed agent could alter what the resident loads at its next launch. The launch dir copies are protected (`resident-memory.md`); the sources are not. The same follow-up covers the EXECUTABLES the resident runs: its Stop hook uses `~/.local/bin/argus`, which links to `~/go/bin/argus`, and both dirs are writable by every sandboxed agent; a native-install `~/.local/bin/claude` has the same problem.
