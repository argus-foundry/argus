## Reference: Plannotator behaviour

Inspected the actual installed bundle at /Users/aaron/.local/bin/plannotator (149,011,298-byte Mach-O, installed October 15). No local source checkout for the upstream UI was found; the executable contains readable minified UI/library source. Findings below come from that embedded source, not guesses or a newly fetched release.

- The Wi enum contains DELETION, COMMENT and GLOBAL_COMMENT. The selection toolbar renders Copy, Delete and Comment plus configurable quick-label/action pickers. Quick labels create COMMENT records, not a separate type. There is no Replace enum/member or replacement toolbar control; we therefore do not invent one.
- The range highlighter captures mouseup/touchend; coarse-pointer selectionchange waits about 400ms before painting a selection. Temporary selection has a floating toolbar; Comment opens an anchored composer/dialog. Delete immediately commits a DELETION/redline with no comment. Global Comment opens an unanchored composer with an Add a global comment prompt.
- Stored highlights include originalText, blockId, startOffset/endOffset and startMeta/endMeta DOM text-position metadata. Restoration first tries stored positions, then quote search; unanchored state is represented rather than losing the annotation. This design adapts that to revision-bound server-verifiable paths/offsets/context and keeps the existing stricter revision conflict contract.
- The embedded highlighter's wrapHighlight preserves earlier IDs in highlight-id-extra while a new overlapping mark gets the primary ID. getHighlightById resolves either primary or extra IDs, so overlapping and identical selections can coexist; primary/newer ID receives direct clicks. The separate page overlay hit test chooses the smallest rectangle, with later-painted annotation winning ties. Decide follows the text highlighter's newest-primary behavior, retaining all overlaps in the panel.
- Sidebar cards show a type label, quoted originalText and comment. COMMENT/GLOBAL_COMMENT have Edit plus Delete annotation; DELETION has removal without a text editor. Card activation is keyboard accessible (Enter/Space). Selecting an annotation applies focused classes, scrollIntoView(center) and a two-second flash; edit supports Save/Cancel, Cmd/Ctrl+Enter and Escape.
- Whole-document GLOBAL_COMMENT exists; Decide maps that to the existing per-item note, labeled General comment, without a second general-comment store. The right column/current-item scope, document-order sorting and phone sheet are deliberate Decide layout choices rather than claims about every Plannotator mode.

## Decisions

Aaron's Plannotator-style correction supersedes the original whole-block/inline-editor interaction. Decisions 3–9 retain their delivery, queue, draft and limit contracts with typed range annotations.

1. **Ranges and anchors:** Select any nonempty span in the current item's body or authored option text, including nested lists, text across paragraphs/bullets, inline formatting/links and option labels/summary/tradeoffs/recommendation reason. Subject, headings and UI controls are excluded, and a range cannot cross item boundaries. Store a stable annotation ID, type (COMMENT or DELETION), the revision, start/end source-field paths and UTF-16 rendered-text offsets, bounded prefix/suffix context (64 Unicode code points each), selected-text hash, server-derived quote preview (up to 512 UTF-8 bytes) and optional comment. Flatten only authored selectable text in document order with a defined newline separator between source fields; offsets ignore markup, highlight wrappers and UI labels. Verify offsets/hash/quote against that revision. Persist range/context to distinguish identical quotes and restore across text nodes; never autoattach stale feedback after revision. A long selection remains intact using offsets/hash while only its displayed quote is shortened.

2. **Selection toolbar and panel:** Follow the installed Plannotator's Copy, Delete and Comment toolbar. Preserve native drag/Shift selection and long-press touch handles; show a small viewport-clamped toolbar after a nonempty valid selection settles. Comment opens a quote-and-comment composer, and Delete immediately saves a deletion suggestion with no required comment. Source text is never modified: Delete renders a red highlight/strikethrough and means a suggestion for the coordinator. Comment renders a distinct highlight. No Replace type or replacement payload is offered because it does not exist in the installed UI. Overlaps, including identical ranges, are permitted as separate IDs; newest paint wins direct hit testing, while all entries remain selectable from the panel; removing one preserves all others. A highlight click selects its entry; Comment offers Edit/Remove, Delete offers Remove. A desktop right-hand panel lists annotations for the current item in document order (start, end, creation sequence), with type, quote and comment. Entry activation scrolls to and flashes the range for two seconds. Clicking/selecting content sets the active item; a compact per-item Annotations button also opens/selects it. On phone, the same panel becomes a labeled modal bottom sheet with Close/Escape, focus trap/restoration and 40px targets. Selection toolbar remains reachable above the OS keyboard/selection handles. Keyboard selection uses the browser selection or a focused passage's Annotate button/Enter fallback selecting that passage, then Tab to toolbar controls. Toolbar and composers must not steal selected text before capturing the range. Plain links still follow on a normal click; selecting linked text, toolbar/highlight activation and annotation controls cannot trigger links or option radio choices. Exclude selection/highlights/panel from tab swipes. Label the existing whole-item note General comment, reflecting Plannotator's global comment; keep required answer-note semantics and route it through the existing note field rather than duplicate it in annotations.

3. **Kinds:** Both decisions and FYIs support the same text-selection and panel flow.

4. **One response:** Saving a valid Comment or Delete annotation queues that item; editor typing alone does not. The existing Review queued groups annotations under their item with annotation type, quoted selection and comment. The single existing Submit actions sends them alongside choice/note/action; Copy responses includes the same context. Remove the last annotation from a comment-only decision to unqueue it unless an explicit comment action with a valid note remains.

5. **No answer:** An annotation-only decision queues Comment, leaves choice empty and stays open after delivery (plain decisions too). Selecting an option turns it into an answer carrying annotations. Something else and plain answers still require their normal answer note; annotations do not substitute for it. On FYIs, saving the first annotation defaults an unset action to Comment. Dismiss plus annotations becomes Comment and dismiss, with an explicit visible label; no silent loss of feedback. Removing annotations does not silently resolve or dismiss anything. A comment may be satisfied by a nonempty note or one saved annotation. Counts and finish handling classify decision comments as comments, not answers; commented decisions stay in open counts.

6. **Delivery:** Extend existing /answers with action ID, action (answer/comment) and annotations; absent action retains ordinary answer behavior. Annotation-bearing answers and all decision comments require durable action receipts. Extend /fyi-actions and its existing receipt path with annotations. No new submit control or transport. Each annotation has type, range/context anchor, derived quoted text and optional full comment; no replacement field is supported; bind it to role/item/expected_updated_at. Commit receipt, item mutation if any and exactly one existing summary per endpoint batch atomically. Add type/quote/comment entries inside that summary; do not send a message per annotation. Existing mixed submissions may produce separate answer-route and FYI-route summaries; this change does not promise a single message across all endpoint batches. Preserve full annotations in receipts, including for resolved answers; extend the existing privileged receipt read path to retrieve decision response receipts as well. Rail-board sessions retain write/replay authority only, never history access. Comments do not change item revision/read state. Identical receipt replay precedes revision/closed checks and emits nothing new. New feedback on closed items is invalid, never reported delivered as already_resolved.

7. **Drafts:** Use existing guarded localStorage response records, never credentials, keyed by role/item/revision. Persist annotations and original quote/path with note drafts and frozen sent payloads before sending. Unknown outcomes lock payload edits/removal until reconciled using the original action ID. On conflict or accepted refresh of a revised item, retain old notes/annotations in a clearly labeled recoverable stale draft, clear pending answer/action and require review plus explicit reanchoring or removal; never attach an old quote to new content automatically. A wholly stale draft does not submit until reconfirmed. Copy remains available for recovery. Storage failures remain visible and do not break rendering. Successful receipts clear only acknowledged annotations.

8. **Caps:** Each Comment annotation requires non-whitespace text at most 4096 UTF-8 bytes; Delete annotations do not require a comment (any supplied comment is capped at the same 4096 bytes), independently of the general note. Maximum 20 annotations per item; 512 UTF-8 bytes per derived quote. Validate both client/server, including multibyte boundaries, unique annotation IDs and valid range/context anchors (overlapping ranges are valid). Show limits before Save; errors retain editor text. Keep 16-item batch limit, adjust bounded request decoding for worst-case annotation size including JSON escapes, and keep summaries at 64 KiB by evenly budgeting general notes and annotation quotes/comments. Every omitted/shortened entry gets a receipt recovery pointer; full feedback remains retrievable. These are bytes, not JavaScript character counts.

9. **Guidance:** Update builtin Hera board guidance, board-tool description and coordinator spawn/reclaim orientation: annotations arrive as type/quote/comment entries, with Delete meaning a suggestion rather than an applied board edit; address each one, retrieve full receipts when truncated, distinguish feedback-only open decisions from answered decisions, and keep settled follow-up reflected on the board. This is a spawn-surface change and requires the inventory/contract checks.

## Risks / tradeoffs

- Selecting text inside options could accidentally answer a decision → separate radio choice labels from authored selectable fields and test pointer/keyboard propagation.
- Revision-local ranges become obsolete after edits → retain stale text and require explicit reanchoring rather than guessing.
- Twenty full comments per item exceed a Hera summary budget → durable full receipts and bounded quoted summaries with pointers.
- A decision resolved elsewhere cannot accept fresh feedback → return invalid for undelivered annotations, preserve drafts and explain the closed item.
