## Context

`ArchivableVerdict` (internal/hera/archive.go) is the done-done gate; `ArchiveHeraUnit` + `archiveUnitChecks` (internal/db/hera_archive.go) are its transactional twin and must stay in lockstep. Facts that shape this design:

- `SetArchived(true)` runs `DELETE FROM task_meta WHERE task_id=?`, so any marker kept in task_meta dies at archive time.
- The PR poller skips archived tasks (`prPollEligible`: `!t.Archived`), and `PRResult` carries no CI state; `PRMergedClosed` collapses merge and close, but `PRResult.Merged` / `Lifecycle()` distinguish them.
- `insertHeraMessage` enforces a sender rate limit (50/min) and a per-recipient unread cap, and refuses archived recipients.
- MCP `task_archive` and REST `setArchive` call `taskDB.Update`/`db.Update` after `task.SetArchived`; TUI calls `db.SetArchived` (local) or REST (remote/web/macOS). `nuke` calls `SetArchived` after it ends the role binding.

## Decisions

**D1. Modes.** One verdict function, three modes: `done` (today's behavior), `handoff`, `forced`. `ArchivableVerdict(store, git, role)` keeps its signature and means `done`; `HandoffVerdict(store, handoff, role)` and the forced path share a private `commonChecks(mode)` so the non-git clauses cannot drift. `archiveUnitChecks(tx, role, taskID, mode)` mirrors it. Handoff differs from done only in: task status may be `in_review` or `complete` (never `in_progress`/`pending`), and the git clause is `HandoffCheck` instead of the merge-safety `GitCheck`. Everything else (not pinned/resident/standing-team, not blocked, no other live binding, no live plan dependents, sub-coordinator children archived and no open decisions, outbox clear) is shared. A role that passes `done` is archived as `merged` (today); otherwise, if it passes `handoff`, as `handed_off`.

**D2. HandoffCheck (daemon-side, fail closed).** One new gitutil call per role: `gh pr view <branch> --json state,isDraft,url,headRefOid,statusCheckRollup` run in the worktree, plus `git ls-remote origin refs/heads/<branch>` and `git rev-parse HEAD`. Archivable only when: PR `OPEN`; rollup state is not `FAILURE`/`ERROR` (pending and no-checks pass; this is "not failing", not "green"); remote tip == local HEAD == PR `headRefOid`; `git status --porcelain` empty. Any command error, missing PR, ambiguous output, or timeout refuses (20s budget like the existing git check). A draft PR is allowed (open + not failing). The check runs before the transaction and is re-run immediately before it opens, exactly like the merged check.

**D3. Durable record, not task_meta.** New table `hera_archive_records(id, role_id, task_id, kind CHECK in ('merged','handed_off','forced'), reason, pr_url, tip_sha, actor_role_id, created_at, settled_at, settle_note)`. A table (not new `hera_roles` columns) because `hera_roles` has ~8 hand-listed SELECT/scan sites and the record needs history (archive, un-archive, re-archive) plus the forced `reason`. Written in the archive transaction. Role history / the TUI inbox viewer read it to render "archived (handed off) / (forced: reason)". `SetArchived`'s task_meta wipe cannot touch it.

**D4. Watching after handoff.** `prPollEligible` gains: an archived task is eligible when it has an unsettled `handed_off` record (`db.HandedOffTaskIDs()` read once per poll). The poll then branches on the existing `res.Merged`/`Lifecycle()`:
- merged: settle the record (`settled_at`, note "merged"); if the task is still `in_review` advance it to `complete` via the existing exact-status-gated helper; post a board `fyi` on the coordinator ("handed-off role X merged"). No role revive.
- closed without merge: **un-archive and revive, plus a board `decision`**. Rationale: a closed-unmerged handed-off PR means the work did NOT land and nobody owns it any more; un-archiving puts it back on the rail (task un-archived, role un-hidden via `UnarchiveHeraRole`, status rolled to `in_progress` via `ReviveHeraWorkerToInProgress`, which is exact-status-gated, no session is started) so it cannot be silently forgotten, and the board item (kind `decision`, so it blocks coordinator sub-archive until resolved) tells the coordinator why. Feasible because both primitives already exist and are idempotent; the poll write is one transaction with the record settle (`settle_note` "closed unmerged"). If revive fails the board item is still posted (never swallow).
- open/other: no-op (state cache still updates).
The merged-notice machinery (`notifyCoordinatorOfMergedPR`/`notifyRoleOfMergedPR`) is NOT used for archived roles: `SendHeraMergeNotice` skips archived tasks and `insertHeraMessage` refuses archived recipients, so the board is the correct channel. Merge notices for unarchived roles are unchanged.
"Batch hands it back" = new coordinator-only `hera_unarchive(cwd, role_name)`: the same un-archive + revive + record-settle ("handed back") in one transaction, no git checks.

**D5. Forced archive.** `hera_archive` gains `force` (bool) and `reason` (required non-empty, trimmed, <= 1 KiB, when force=true; rejected if force is false). Force requires `role_name` (never a sweep: a bulk override is too easy to fire by accident). Under force the done-done/handoff/inbox/outbox/dependents/children/git/status/session-busy checks are skipped (a live session is still stopped after commit), but these stay hard in BOTH the preflight and the transaction: coordinator role, pinned role/task, resident task, standing-team member, role already archived/nuked/cancelled, and "task also bound to another live role" (archiving the task would strand that role). The record is `kind=forced` with the reason, and a forced archive of a role that also satisfied handoff is still recorded `forced` (the caller asked for it). Reason is also appended to the forwarded mail digest so the coordinator's inbox shows it.

**D6. Unread mail forward.** Replace the inbox blocker with: in the archive transaction, mark the role's unread non-merge-notice hera mail read and insert ONE digest message from the archived role to the orchestrator's first live coordinator (tldr `archived <role>: N unread message(s) forwarded`, body = one line per message: `#<id> from <sender role>: <first line, truncated 200 B>`). One digest rather than N forwards because the 50/min sender cap and the coordinator's unread cap would otherwise make a sweep fail. If the digest insert fails (coordinator inbox full, rate limit) the whole archive rolls back and refuses with that reason: no mail is ever marked read without its summary being delivered. Messages still exist in `hera_messages` (hera mail persists through archive), so the full body stays retrievable via `hera_get_messages`. Post-commit the daemon best-effort rings the coordinator doorbell for the digest (same `Deliver` path as other notices). The **outbox check stays** for done and handoff: an unread message from this role is an unanswered report or question to someone still live, and archiving silently would bury it; `force` overrides it.

**D7. Argus archive agrees with hera archive.** Layers:
1. `hera.ArchiveTaskGuard(store, runner, git, task, force, reason)` is the one entry for argus-side archives. No live non-coordinator hera binding: pass through (plain tasks unchanged). Live worker/freelance binding: run the same `ArchiveRole` (done→handoff, or forced) so the role archives together with the task in ONE transaction; on refusal return a typed `*ArchiveRefusedError{Reason}`. A live coordinator binding refuses (a coordinator is archived from hera, not argus) with the existing coordinator reason.
2. Wired into MCP `task_archive`, REST `setArchive` (covers web, macOS, remote TUI), and the local TUI `OnArchive` (local mode builds the same checks from `internal/hera` constructors; the production `GitCheck`/`HandoffCheck` constructors move out of `internal/daemon` into `internal/hera` so TUI and daemon share them). Unarchive (archived=false) is unguarded for plain tasks; for a hera-bound task with an archive record it is the same as `hera_unarchive`.
3. **DB backstop**: `db.SetArchived(id, true)` and the archived 0→1 flip inside `db.Update` refuse with `ErrHeraRoleLive` when the task has a live worker/freelance binding. `ArchiveHeraUnit` uses the unexported `setArchivedTx` directly, and nuke ends the binding before it archives, so neither trips it (task 5.x audits every `SetArchived`/`Update` caller). This closes "no side door" even for a future caller that forgets the guard.
Refusal message: `<reason>. To override, a coordinator can call hera_archive(role_name=…, force=true, reason=…)` (humans: see D8).
The reverse already holds: `hera_archive` archives the task inside `ArchiveHeraUnit` (`setArchivedTx`); the design only adds a test pinning it. Out of scope and unchanged: the rail `a` HIDE key, which hides a role without archiving the task (a different, deliberate, human-driven operation).

**D8. Human override.** The brief's "suggest forced hera_archive" is unusable by a human in the TUI/web. REST archive accepts `{"force":true,"reason":"..."}` (reason required) which runs the forced path; TUI shows the refusal in a notice and offers a confirm modal to force (reusing the `graduationPendingEscape` pattern, reason auto-filled `forced from TUI`). Web and macOS show the 409 reason; their force affordance is a named follow-up (below).

**D9. CI in the poller query.** `FetchPRStatesBatch` gets `commits(last:1){nodes{commit{statusCheckRollup{state}}}}` in its aliased query and `PRResult.CI` (informational; not persisted). Only the handoff check consumes it directly (D2 uses `gh pr view` for one-off precision); the poller does not act on CI.

## Frontend parity (TUI / web / macOS)

The change adds a REST behavior change (archive endpoint can now 409 with a reason and accept a force body) and no new event or field, so all three clients are evaluated:

- **TUI**: handled in this change (refusal notice, force confirm, handed-off/forced label in the Hera rail role row and inbox viewer).
- **Web (SPA/PWA)**: gets the 409 reason as an error toast through its existing error path (verify in tasks; bump `SW_VERSION` only if shell assets change). **Named follow-up**: a "force archive" affordance.
- **macOS**: `ArgusKit` surfaces the 409 as an archive error (verify). Archive label ("handed off") display and the force affordance are **named follow-ups** (macOS Hera tab is read-only today by design).
- `hera_unarchive` and `force` over MCP are agent-facing only; no client equivalent (like `hera_archive` itself).

## Risks / trade-offs

- `gh`/`git ls-remote` outages refuse (safe direction); coordinators retry.
- A handed-off role whose PR is later force-pushed has local != remote only at archive time; later divergence is the batch's business and is not re-checked (documented in the skill).
- The backstop turns previously "successful" argus archives of live-bound tasks into refusals. Intentional and single-user; scripted callers get the 409 reason.
- Poll-time un-archive resurrects a role on the rail; if the coordinator is gone (orchestrator archived/nuked) the revive is skipped and only the log line remains (the role has no live coordinator to hand back to).
