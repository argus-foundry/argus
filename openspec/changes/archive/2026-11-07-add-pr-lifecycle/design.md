## Decisions

- **Storage:** `lifecycle` is a third key in the existing `pr` namespace, written in the same `SetMetaBatchIfChanged` transaction as `state`/`url`, so one commit yields one `task.pr_changed`. A column was not needed: the value is refreshed by the poller and not an archive-surviving timestamp.
- **Derivation:** `gitutil.PRResult.Lifecycle()` — `Merged` gives merged; merged-closed without MERGED evidence gives closed; no PR or unknown gives unknown; everything else is open.
- **DTO projection:** `model.ResolvePRLifecycle(state, lifecycle)` prefers a verified stored value. A non-terminal `pr_state` (including draft) with no stored value projects `open`, since a non-terminal state can only come from an open PR. A merged-closed entry without a merged or closed lifecycle projects `unknown`, including a stale open lifecycle retained by an older binary.
- **Terminal refresh bound:** the poller skips a terminal entry only when its stored lifecycle is merged or closed. Unverified terminal entries get one immediate attempt per task per daemon process in the existing batched query, then use dormancy cadence for unsuccessful retries. A successful fetch writes the lifecycle and the entry is skipped from then on. A fetch error or omitted branch keeps the cached values. Attempt tracking is an in-memory set owned by the serial daemon poller, with no new storage key.
- **Event:** `model.PRChangedPayload` is a struct so a later change can add a link `source` key additively. `task.updated` with `pr` still fires from the meta write; `task.pr_changed` carries the PR facts for consumers that do not want to re-read.
- **Rollout:** the next poll makes the one immediate verification attempt for unverified terminal caches regardless of dormancy and emits `task.pr_changed` on change, without repeating historical merge notices. Non-terminal entries retain their existing dormancy and open-PR cadence.
- **Deviation:** none from the ticket contract.
